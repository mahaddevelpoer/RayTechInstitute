## Easy topic-wise notes

## 5.1 Operating Systems and System Software

System software manages or supports the operation of a computer. Its main examples include operating systems, device drivers and utilities. An operating system, or OS, manages resources and provides services that programs and users can request. A word processor helps create a document; the operating system supplies services for memory, files, devices and controlled execution.

The kernel is the central part of an operating system responsible for core resource management and protected operations. It is not the entire visible desktop. A shell provides a way to interact with the system; it can be command-based or graphical. A graphical user interface, or GUI, uses visual controls such as windows, icons and menus. A command-line interface, or CLI, accepts textual commands. One OS can support both interfaces. Appearance alone does not identify every internal part of the system.

A program is a stored set of instructions; a process is an executing instance with state and resources. Opening the same application twice may create multiple processes, depending on the application design. A device driver participates in communication between the operating system and a device. The OS may already include a suitable driver, or a supported vendor package may be required. A printer connected to a port is not proof that the correct driver, settings and permissions are available.

Firmware and the OS have different roles. In a simplified startup model, firmware performs initial platform work, a bootloader loads the operating-system kernel, and the system starts required services and a user environment. The exact sequence varies by platform. Modern general-purpose operating systems are commonly installed on persistent storage and load required components into memory during operation. An OS is not simply another name for BIOS or UEFI, and it is not necessarily stored entirely in read-only memory.

Operating systems enforce boundaries between accounts and programs, but the strength of those boundaries depends on design and configuration. Standard accounts normally have fewer administrative powers than administrator accounts. Privilege is authority to perform an operation, not proof that the requested operation is sensible. Select compatible software and drivers, use supported versions and obtain changes from trustworthy sources. Names, desktop layouts and menu paths can vary between versions without changing the basic roles described here.

### Practical examples

- A word processor requests an OS file service when a student saves a document.
- A system may offer both a graphical file manager and a command shell.
- A supported printer driver lets the OS communicate with a particular printer or device class.

### Common mistakes

- The kernel is not the entire desktop or every installed application.
- A driver is software, not the cable connecting a device.
- Firmware, bootloader and operating system are different parts of startup.

### Quick revision

- System software supports computer operation.
- The OS manages resources and offers services.
- The kernel carries out core system work.
- GUI and CLI are interface styles.
- A process is an executing program instance.
- Drivers support OS-device communication.

## 5.2 Functions of an Operating System

Starting and shutting down are coordinated system operations. During startup, required OS components and services become available. During a normal shutdown, the system closes or stops work and handles pending operations according to its design. Save documents first and allow supported update or shutdown operations to finish. Turning off power is not a routine substitute for an orderly shutdown.

The OS provides a user interface and manages programs. It creates and tracks processes, supplies execution services and helps control their access to resources. The scheduler chooses runnable work for processor time. A single CPU core can alternate among tasks, making progress on several activities over time; it does not execute every instruction of every task simultaneously. Multiple cores can execute work in parallel when the software and conditions permit.

Memory management tracks and allocates memory and supports protection between processes. Virtual memory gives a process an address-space abstraction; operating systems may use storage-backed paging as part of their memory management. A paging file does not become equally fast physical RAM, and not every virtual-memory page must be on disk. Excessive paging can affect responsiveness. Managing memory and scheduling CPU time are related resource functions but not the same operation.

Device configuration uses drivers and settings to communicate with hardware. Network services support communication, while reaching the Internet also requires a working connection, addressing, name resolution and the relevant network/provider service. An OS setting alone cannot create a paid Internet connection or repair every external outage. File management organises files and directories, records properties and enforces supported access permissions. A displayed shortcut is a reference, not necessarily the file's full contents.

Performance monitoring reports observations such as CPU activity, memory use, storage activity and network traffic. A high reading can be normal during demanding work; one graph alone does not prove malware or hardware failure. Automatic updating can help maintain supported system components, but successful download, installation and any required restart are separate states. Review status and follow the organisation's update policy rather than assuming enabled automation guarantees completion.

Network control includes authorised sharing, user access and service configuration. Security administration includes authentication, permissions, account privileges and security settings. Authentication checks a claimed identity; authorisation decides what that identity may do. The OS supports these controls, but users still need appropriate permissions, sound configuration and recoverable copies. Security, networking, file management and updates support one another without making any single feature a guarantee against every problem.

### Practical examples

- The scheduler shares processor time between a lesson player and a document editor.
- A file permission allows students to read a handout while limiting who can change it.
- A performance graph shows high CPU use during a video export; the workload explains the reading.

### Common mistakes

- Multitasking does not mean every task runs at the exact same instant on one core.
- Disk-backed paging is not the same thing as adding equally fast RAM.
- A downloaded update or enabled automatic setting does not prove successful installation.

### Quick revision

- Startup and shutdown coordinate system work.
- The OS manages processes and CPU scheduling.
- Memory management allocates and protects resources.
- Drivers and network services support connectivity.
- Monitoring provides evidence to interpret.
- Authentication and authorisation have different roles.

## 5.3 Operating System Types: Windows and Linux

Operating systems can be grouped by intended role. A stand-alone or desktop OS supports a computer's local user tasks, such as editing documents and using applications. Stand-alone does not mean the system cannot join a network. A desktop can still access shared resources or provide limited sharing. The category describes a main role rather than isolation from all other devices.

A server OS is configured to provide services to clients, such as shared files, authentication, application hosting or printing. Server operation often emphasises availability, access control, remote administration and service management. A server may be administered through a CLI or a GUI, locally or remotely. The absence of a monitor does not mean an operating system is absent. One machine can perform several roles, and capabilities depend on the edition and configuration.

An embedded OS operates within a larger product or specialised device. Examples can include an industrial controller, a network appliance or a smart device. Some embedded systems require predictable responses under time constraints. A real-time system aims to meet relevant timing deadlines; real-time does not simply mean the highest average processing speed. Not every embedded product has the same requirements or uses an identical OS.

Windows is an operating-system family with different products, releases and editions. Features, supported hardware, application compatibility and update/support lifecycle depend on the exact version. Do not assume that every historical Windows release still receives ordinary security support. For actual maintenance, check the official lifecycle and the institution's approved configuration instead of relying only on the familiar product name.

Linux is the name of a kernel and is also commonly used to describe complete operating systems built around it. A Linux distribution combines the kernel with selected tools, libraries, package management and often a desktop environment. Ubuntu is one example of a distribution, with desktop and server uses. Linux systems are not limited to a CLI, and open-source components do not imply that every accompanying product or support service has identical licensing or no cost.

Select an OS by required applications, device support, security/update maintenance, user accessibility, administration and relevant licensing. A program made for one OS is not automatically compatible with another, even if both systems show similar icons. Web applications, compatibility layers and virtual machines can provide different approaches, but none proves universal compatibility. The categories desktop, server and embedded can overlap in capabilities; use the stated workload and configuration to explain your classification.

### Practical examples

- A network-connected classroom desktop remains a desktop system when local student work is its main role.
- A Linux-based server can provide files without a permanently attached monitor.
- An embedded controller with timing deadlines is evaluated by meeting those deadlines, not by a desktop-style speed ranking.

### Common mistakes

- Stand-alone does not mean incapable of networking.
- Linux systems can provide graphical desktops as well as command shells.
- Server, desktop and embedded describe roles; they are not determined only by cabinet size.

### Quick revision

- Desktop systems support local user work.
- Servers provide services to clients.
- Embedded systems operate within larger products.
- Real-time concerns timing requirements.
- Windows has version-specific features and support.
- A Linux distribution includes a kernel and additional components.

## 5.4 Operating System Utility Programs

Utilities perform supporting tasks such as file handling, inspection, recovery and security management. Some are included with an OS while others are installed separately. The syllabus groups several familiar tools here; this grouping does not mean every platform bundles the same tool or classifies every media application identically. Learn each function rather than assuming a name proves inclusion.

A file manager browses folders and performs permitted file operations. A search utility locates matching items within its search scope; indexing and permissions can affect results. An uninstaller uses the supported removal process for an installed program. Deleting a shortcut normally removes a reference rather than uninstalling the application. An image viewer displays pictures, while a media player presents supported audio or video. A file extension is a naming clue, not a guarantee of content or decoder compatibility.

Disk cleanup tools identify selected files or categories for removal to reclaim storage. Review the categories: a downloads folder or recycle bin can contain work still needed. Do not confuse deletion with backup. HDD defragmentation can reorganise fragmented file extents to reduce avoidable mechanical seeking. SSDs have a different access mechanism; supported optimisation can include TRIM or retrim, which informs storage about unused ranges. Use the OS's appropriate supported maintenance rather than forcing repeated HDD-style defragmentation on an SSD. Optimisation is not the same as formatting a drive.

Backup utilities create recoverable copies according to their scope and retention settings. Restore utilities recover saved content. A system-settings recovery feature may have a different scope from a personal-file backup; inspect what is included. Test a sample restore to another location. A screen saver changes or blanks the idle display and is not automatically a security lock. Requiring authentication on return is a separate setting. Display sleep and screen-saver animation also do not necessarily use the same amount of power.

A firewall applies rules to network traffic. Antivirus or anti-malware tools detect and respond to suspected malicious software using supported methods and updates. A firewall is not a substitute for scanning, and a clean scan is not proof of perfect safety. Spyware aims to collect information covertly or without appropriate consent. Adware displays advertising and can be unwanted or bundled; classify the actual behaviour rather than assuming every advertisement is malware. Use trusted tools and review detections under the relevant policy.

File compression reduces size where the data allows. A lossless archive can restore the original bytes; it does not guarantee that every file becomes much smaller. Already compressed media may gain little. Compression is not encryption or backup. Disc-burning software records supported data to compatible optical media using a suitable writer; a reader is not automatically a burner. Finish recording and verify the intended files. Always distinguish viewing, copying, compressing, protecting and restoring instead of treating every utility as a universal repair tool.

### Practical examples

- Search within a permitted folder for a known practice filename, then check its path and contents.
- An uninstaller removes an application through its supported process; deleting its desktop shortcut does not do the same job.
- A backup utility recovers a sample file separately, while a firewall applies network-traffic rules.

### Common mistakes

- Cleanup can delete needed files if categories are not reviewed.
- A screen saver is not automatically a lock, and compression is not encryption.
- HDD defragmentation and supported SSD optimisation are different operations.

### Quick revision

- File managers and search utilities locate and organise resources.
- Use a supported uninstaller for application removal.
- Review cleanup choices before deletion.
- Use storage-appropriate optimisation.
- Backup and restore must be checked by scope and recovery.
- Firewall, anti-malware and compression have distinct jobs.

## 5.5 Personal Computer Maintenance

Personal computer maintenance is planned care that helps keep equipment usable, supported and recoverable. Preventive work includes appropriate updates, verified backups, sensible storage management and physical care. Corrective work investigates a reported fault and addresses its cause. Neither a cleaner application nor one security scan can promise that every computer will remain fast or fault-free.

Begin with observation and protection of work. Record the symptom, when it began, affected applications and any error text without exposing passwords or private content. Save current work and confirm important recovery copies before a change that could affect files or configuration. Check simple causes such as a loose external connection, low free storage, unavailable network service or an application-specific problem. Do not infer one universal cause from a single slow response.

Use a supported update channel for the OS and approved software. Driver updates should match the actual device and platform. Read relevant instructions, maintain suitable power during an update and allow completion; required restarts should be planned after saving work. Firmware updates are model-specific changes and are not casual classroom experiments. Untrusted driver-updater advertisements or a program claiming thousands of urgent faults are not evidence that their proposed changes are needed.

Inspect storage usage and identify the owner and purpose of data before cleanup. Keep adequate working space, but do not delete unknown system folders to meet an arbitrary target. Review startup items and background workloads only within authorised settings. Use performance observations to form a hypothesis, change one relevant factor at a time where practical, and retest the original task. A restart may clear a temporary condition, but improvement after restarting is not a diagnosis of every underlying cause.

For physical care, follow the exact equipment instructions. Shut down and disconnect power as directed before permitted cleaning. Keep ventilation openings clear, use suitable cleaning materials and avoid liquid entering equipment. Do not open a power supply, CRT or other high-voltage assembly. Internal work and battery servicing require the appropriate skills and product procedures; an external classroom inspection does not require disassembly.

Protect accounts, keep appropriate security controls active and use trusted software sources. If a tool reports a threat, preserve relevant evidence and follow the institution's response process rather than indiscriminately deleting files or disabling protection. Test restored samples and confirm required access, media and keys. Document the change, observed result and remaining issue. A good maintenance record states what was checked and measured instead of asserting that a single action guarantees complete security or a permanent speed increase.

### Practical examples

- A student records a slow-save symptom, checks free storage and compares the same task after an approved change.
- A teacher saves work and schedules a required update restart outside the lesson.
- A permitted external cleaning task follows the manufacturer’s power and cleaning instructions without opening electrical assemblies.

### Common mistakes

- Do not delete unknown system files or disable protection as a general speed fix.
- High resource use or an alarming advertisement is not a diagnosis by itself.
- A successful copy notification is weaker evidence than a checked restoration.

### Quick revision

- Maintenance includes prevention and fault investigation.
- Record symptoms and protect work first.
- Use supported update and driver sources.
- Review storage choices and permissions.
- Follow product-specific cleaning instructions.
- Retest and document the actual outcome.

## Solved short questions

### 1. Define system software and name three examples.

System software manages or supports computer operation. Examples include an operating system, a device driver and a supporting utility. A word processor is normally application software for a user task.

### 2. Distinguish kernel and shell.

The kernel performs core OS resource-management and protected operations. A shell provides an interaction environment, which can be textual or graphical. Neither term means every installed application.

### 3. Distinguish a program from a process.

A program is a stored set of instructions. A process is an executing instance with state and resources. Multiple instances may use the same stored program, depending on the application design.

### 4. Explain the role of a device driver.

A driver participates in communication between the operating system and a device. It must be suitable for the device and platform. A physical connection alone does not establish driver or configuration readiness.

### 5. How does CPU scheduling support multitasking?

The scheduler allocates processor time to runnable work. A single core can alternate among tasks; multiple cores can execute some work in parallel. Multitasking does not imply all instructions run at the same instant.

### 6. Why is virtual memory not simply extra equally fast RAM?

Virtual memory provides an address-space abstraction, and paging may use persistent storage. Storage-backed access has different performance from physical RAM. Not every virtual-memory page is necessarily on disk.

### 7. Compare desktop, server and embedded OS roles.

Desktop systems support local user tasks, servers supply services to clients, and embedded systems operate within larger products. Capabilities overlap, so role and configuration matter more than cabinet size.

### 8. What is a Linux distribution?

It combines the Linux kernel with selected tools, libraries and other components, often including package management and a desktop environment. Linux-based systems can provide GUI and CLI interaction.

### 9. Distinguish firewall and anti-malware software.

A firewall applies rules to network traffic. Anti-malware tools detect and respond to suspected malicious software. Their functions complement one another; neither guarantees perfect protection or replaces recoverable copies.

### 10. Compare HDD defragmentation and SSD optimisation.

HDD defragmentation reorganises fragments to reduce avoidable seeking. Supported SSD optimisation can include TRIM/retrim for unused ranges. Use storage-appropriate OS maintenance rather than forcing repeated HDD-style defragmentation on an SSD.

### 11. How do backup and restore utilities differ?

Backup creates retained recoverable data within a defined scope and policy. Restore recovers that data. Verify a sample in a separate location and check what the selected feature actually includes.

### 12. State a sound maintenance sequence.

Record the symptom, save and protect work, check simple causes, make an authorised relevant change, retest the original task and document the result. Use supported sources and model-specific handling instructions.

## Solved long questions

### 1. Explain operating-system structure and startup using a saved document example.

**Core roles.** The OS manages resources and supplies services. Its kernel handles core system work. A shell provides interaction through a command environment or graphical interface. An application performs the document-editing task.

**Running work.** The stored application program can create a running process. The OS tracks execution and resources, manages memory and uses drivers for supported devices. The document contents are user data rather than the OS itself.

**Startup.** In a simplified model, firmware performs initial platform work, a bootloader loads the kernel, and services and a user environment start. Platform details vary. Firmware and the OS are not the same program.

**Saving and closing.** The application requests file services to save work to persistent storage. Before normal shutdown, save documents and allow supported operations to complete. A visible document or closed window alone does not prove a recoverable copy exists.

### 2. Describe the operating-system functions named in the syllabus.

**Startup and interaction.** Coordinate startup and shutdown and offer a user interface. Start and manage program instances and expose services for user work.

**Resource coordination.** Allocate and protect memory, schedule runnable work for CPU time and configure supported devices through drivers and settings. Virtual memory and CPU scheduling address different resources.

**Files, connections and monitoring.** Organise files and permissions, support network/Internet communication and report resource activity. Reaching the Internet also depends on the external connection and relevant services. Interpret performance observations in context.

**Updates, networks and security.** Apply supported update policy, configure authorised network services and administer accounts and access controls. Check completed installation and required restarts. Authentication checks a claimed identity; authorisation determines permitted actions.

### 3. Compare desktop, server and embedded systems and discuss Windows/Linux selection.

**Roles.** Desktop systems support local applications and can still use networks. Server systems provide services to clients. Embedded systems support functions inside a larger product. Some embedded workloads have timing deadlines.

**Windows.** The Windows family has different products, releases and editions. Features, device support, application compatibility and lifecycle must be checked for the actual version. A familiar brand does not prove continuing security support.

**Linux.** A distribution combines the Linux kernel with selected system components. A desktop environment and command shell can both be available. Ubuntu is one example used for desktop and server roles.

**Selection.** Check the required workload, applications, device support, accessibility, administration, licences and maintenance. A similar desktop appearance is not proof that every application runs unchanged across platforms.

### 4. Explain the utility programs listed by the syllabus and distinguish their functions.

**Files and presentation.** A file manager organises files; search locates matches within scope. An uninstaller removes supported applications. An image viewer presents pictures and a media player presents supported audio/video. Deleting a shortcut is not normally uninstalling.

**Storage and recovery.** Cleanup removes selected items and needs review. HDD defragmentation differs from supported SSD TRIM/retrim. Backup retains recoverable data and restore retrieves it. Check scope and test a sample.

**Security and idle display.** A firewall applies network rules. Anti-malware tools handle suspected malicious software; spyware and unwanted adware have relevant behaviours. A screen saver changes an idle display, while locking and return authentication need their own configuration.

**Packaging and recording.** Lossless compression can recover original bytes, but size savings depend on input and compression does not itself provide encryption or independent backup. Disc burning needs compatible writable media, a supported writer and completed verified recording.

### 5. Develop a controlled plan for investigating a slow classroom computer.

**Observe and protect.** Record when the slowdown occurs, which task is affected and relevant messages without exposing secrets. Save work and confirm important recovery copies. Ask whether the issue affects one application or the whole system.

**Check evidence.** Observe resource activity and storage availability, relevant external connections and the network path. A high CPU value alone does not establish malware. Identify a plausible cause before changing settings.

**Act within scope.** Use approved updates and appropriate settings. Review cleanup categories and application removal before acting. Do not delete unknown system folders, install untrusted repair tools or disable protection as a general fix.

**Retest and record.** Where practical, change one relevant factor, repeat the same task and record the outcome. Escalate hardware or persistent faults through the proper support process. Temporary improvement is useful evidence rather than proof of a universal diagnosis.

### 6. Design an ongoing maintenance and recovery routine for a student workstation.

**Supported software.** Maintain the approved OS and applications through supported channels. Match drivers to devices, plan required restarts and follow model-specific firmware guidance. Preserve appropriate security settings.

**Files and recovery.** Save work in the intended location, keep suitable separate recovery copies and review retention. Test restoration to another location and open the recovered sample. A settings rollback feature may not cover personal documents.

**Physical care and access.** Follow the equipment maker’s cleaning and power instructions, keep ventilation clear and leave high-voltage assemblies closed. Lock the workstation when away and use appropriate account privileges and sharing permissions.

**Record and adapt.** Record performed checks, dates, observed results and unresolved problems. Adjust the routine to actual equipment, workload and institutional policy. No single cleaner, scan or maintenance action guarantees permanent performance or perfect security.

## Practical activities and viva preparation

### Identify OS, interface and device information

On a permitted computer, use existing read-only system information and settings to record the OS name/version, an available GUI or CLI, and one identified device/driver entry. Hide personal identifiers in any shared record. Do not install, uninstall or replace anything.

**Expected result:** A labelled distinction between OS, interface and driver, with uncertain details recorded honestly.

### Observe processes and resource activity

Open the supported performance/process viewer on a permitted device. Observe CPU and memory activity during an already available non-sensitive application task. Record two observations without ending system processes or changing priorities.

**Expected result:** A description of running work and resource use that does not treat one high reading as proof of malware.

### Find and compress a practice file

Create a non-sensitive text sample in an approved practice folder. Find it using the file manager/search. If built-in lossless archive tools are available, make an archive, extract to a separate folder and compare the recovered contents. Retain the source.

**Expected result:** Correct paths, a readable recovered sample and a distinction between search, compression, encryption and backup.

### Review maintenance settings without changing them

Observe existing update, storage-optimisation, security and screen-lock information where your account permits. Note which device is HDD/SSD if documented, what actions would need authorisation and whether a restart is shown as required. Do not delete files, disable protection or force optimisation.

**Expected result:** A review table that separates observation from proposed changes and distinguishes optimisation, cleanup and lock settings.

### Demonstrate a checked recovery and document it

Using only a non-sensitive sample and approved locations, retain the original, make a separate recovery copy, restore or copy back to a different practice folder and compare contents. If a backup utility is already authorised, identify its scope; otherwise model the backup/restore plan on paper.

**Expected result:** A maintenance note with symptom or purpose, source/destination, observed result and limitations; no destructive deletion is required.
