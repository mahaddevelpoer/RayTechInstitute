## Topic-wise revision MCQs

## 7.1 Networks, Internet Access and Addresses MCQs

### Q1. What is the Internet?

A) Only one classroom's printer cable

B) Only the physical monitor on a desk

**C) A global interconnection of networks**

D) Only a single social-media website

**Correct answer: C.** The Internet connects many networks rather than being one application or local link.

### Q2. Does a Wi-Fi connection alone prove external Internet access?

**A) No, the router connection can work while external access fails**

B) Yes, every connected router guarantees all websites work

C) Yes, Wi-Fi creates every paid access service automatically

D) No, because Wi-Fi can never carry Internet traffic

**Correct answer: A.** Local connectivity and the external service path are separate requirements.

### Q3. What is the role of an ISP?

A) Only organise desktop icons

**B) Provide an Internet access service**

C) Only supply a word-processing font

D) Only increase CPU register size

**Correct answer: B.** An ISP supplies the connectivity service through supported access methods.

### Q4. Which is an example of an Internet access method?

**A) Fibre or mobile-network access**

B) Only a printer's paper setting

C) Only a screen-saver animation

D) Only a keyboard shortcut

**Correct answer: A.** Different access technologies provide links to a provider network.

### Q5. What does a router primarily do?

A) Guarantee every document is truthful

B) Act only as a camera lens

C) Replace all application software

**D) Forward traffic between networks**

**Correct answer: D.** Routing selects and forwards traffic through the network path.

### Q6. Which statement about a combined home-network device is accurate?

A) Every hardware function has an identical technical meaning

B) A router and a text editor are always the same component

**C) One product can combine routing and wireless access functions**

D) A Wi-Fi label proves all modem types are included

**Correct answer: C.** Physical products can combine distinct networking roles.

### Q7. How can Internet data travel?

**A) In packets through a sequence of network links and routers**

B) Only as one physical paper sheet

C) Only through the same unchanging route for every packet

D) Only by a user retyping every byte at each router

**Correct answer: A.** Packet communication allows networks to carry data across multiple links.

### Q8. Which statement about delivery reliability is correct?

**A) It depends on protocols and application design**

B) Every Internet packet has an identical guaranteed arrival time

C) All transport protocols behave exactly like TCP

D) No application can ever recover from a lost packet

**Correct answer: A.** Different protocols provide different delivery and recovery properties.

### Q9. What does an IP address help identify?

A) Only a person's legal identity

**B) An interface for IP communication within its scope**

C) Only a file's font

D) Only a printer's ink colour

**Correct answer: B.** An IP address is a network addressing value, not a universal identity certificate.

### Q10. What is a main purpose of DNS?

A) Convert every image to a printed page

**B) Resolve names to relevant records, including address records**

C) Supply electrical power to an ISP

D) Guarantee a website's claims are true

**Correct answer: B.** DNS supports naming and lookup rather than verifying every site's content.

### Q11. What does latency describe?

**A) Communication delay**

B) Only the total storage capacity of an SSD

C) Only a network cable's colour

D) The number of words in a document

**Correct answer: A.** Latency measures delay and differs from transfer throughput.

### Q12. Before overhead, what is 100 megabits per second expressed in megabytes per second?

A) 100 MB/s

B) 800 MB/s

**C) 12.5 MB/s**

D) 0.125 MB/s

**Correct answer: C.** Eight bits make one byte, so the stated rate is divided by eight.

## 7.2 The World Wide Web and Web Publishing MCQs

### Q13. How does the Web relate to the Internet?

A) It is universally the same thing as every Internet service

B) It means only the physical network adapter

C) It excludes all browsers

**D) It is a major linked-resource system using Internet connectivity**

**Correct answer: D.** The Web is one use of the broader Internet infrastructure.

### Q14. What is the role of a browser?

A) Guarantee all search results are correct

B) Act as every site's author

C) Replace every network service provider

**D) Retrieve and present web resources**

**Correct answer: D.** Browsers provide an environment for accessing and displaying resources.

### Q15. How does a search engine differ from a browser?

A) They are always identical names for the same software

B) A search engine is only a keyboard device

C) A browser cannot access a search service

**D) It helps locate indexed material rather than being the general browsing program**

**Correct answer: D.** The browser can access many services, including search engines.

### Q16. Which URL component identifies the service name in a simple web address?

A) Only the displayed link colour

**B) Host**

C) Only the paragraph heading

D) Only the file's printed title

**Correct answer: B.** The host is an address component distinct from scheme, path and other parts.

### Q17. What does a URL path commonly identify?

**A) A resource location within the named service**

B) The user's automatic legal identity

C) The physical length of a network cable

D) The screen's refresh frequency

**Correct answer: A.** A path helps select the requested resource within the service.

### Q18. Does a link's visible text prove its destination?

A) Yes, every label is independently verified by the browser

**B) No, the destination address should be inspected where relevant**

C) Yes, any familiar word guarantees a trusted login page

D) No, because links can never contain text

**Correct answer: B.** Displayed text and the linked URL can differ.

### Q19. What does refreshing a web page fail to guarantee?

A) That the browser can request a resource

B) That a page has an address

**C) That every upstream source has instantly produced new data**

D) That servers can return content

**Correct answer: C.** Caching and source update timing affect what a refreshed page displays.

### Q20. What is an appropriate search-result check?

**A) Open the source and review its date, evidence and purpose**

B) Assume the first result is always an official authority

C) Use the snippet alone for every deadline

D) Treat every advertisement as a verified public notice

**Correct answer: A.** Search ranking is not a substitute for evaluating the underlying source.

### Q21. Which classification of websites is sensible?

**A) Sites can combine educational, commercial or other purposes**

B) Every site has exactly one possible function forever

C) A site with pictures can never be educational

D) Every community post is an official regulation

**Correct answer: A.** Categories describe purpose and can overlap.

### Q22. What does HTTPS alone not establish?

A) That the service uses a web address

B) That encrypted transport can be used

C) That a browser can make a request

**D) The truth of every claim on a page**

**Correct answer: D.** Transport security and factual reliability are separate questions.

### Q23. How does a local preview differ from publishing?

**A) A preview is not necessarily available to the intended external audience**

B) Every local file is automatically public worldwide

C) Previewing always creates a hosting account

D) Publishing never needs any verification

**Correct answer: A.** Public availability requires the supported delivery and access configuration.

### Q24. What should follow a web publishing change?

A) Assume all content is correct because an upload started

**B) Verify the delivered page, links and intended access**

C) Expose private records to test publicity

D) Remove all source attribution automatically

**Correct answer: B.** A successful change needs checks of actual output and permitted content.

## 7.3 E-Commerce MCQs

### Q25. What is e-commerce?

**A) Electronic support for buying, selling and related transactions**

B) Only changing a computer's wallpaper

C) Only an offline printed product label

D) Only a processor's instruction cycle

**Correct answer: A.** E-commerce concerns electronic transaction workflows.

### Q26. Which example is B2C?

A) A business purchasing supplies from another business

B) Only two servers exchanging clock signals

C) Only a printer producing a test page

**D) A retailer selling an item to an individual customer**

**Correct answer: D.** B2C describes business-to-consumer transactions.

### Q27. Which example is B2B?

A) Only a student viewing a personal photograph

**B) One business buying supplies from another business**

C) Only a keyboard typing a search term

D) Only two unrelated display pixels

**Correct answer: B.** B2B describes transactions between businesses.

### Q28. What can C2C describe?

**A) Individuals selling to other individuals through a marketplace**

B) Only the CPU contacting its cache

C) Only a government publishing a timetable

D) Only a school setting a password policy

**Correct answer: A.** C2C describes a consumer-to-consumer relationship.

### Q29. Does a marketplace necessarily manufacture every listed item?

A) Yes, every platform makes every product itself

B) Yes, the logo proves all items have one manufacturer

C) No, because marketplaces cannot support orders

**D) No, the platform and seller roles need checking**

**Correct answer: D.** A marketplace can connect sellers and buyers without making every product.

### Q30. In the stated example, what is 1,000 plus 150 delivery minus a 100 discount?

**A) 1,050**

B) 1,250

C) 950

D) 850

**Correct answer: A.** The fictional total is 1,050, assuming no additional charges.

### Q31. What should a buyer compare at checkout?

A) Only the largest crossed-out number

**B) The complete payable amount and relevant conditions**

C) Only the page's background colour

D) Only the number of advertisement images

**Correct answer: B.** Fees, valid discounts and conditions can change the actual total.

### Q32. Does paid order status always mean delivered?

A) Yes, payment physically transports the goods

B) Yes, every confirmation means delivery is complete

**C) No, payment and fulfilment are different stages**

D) No, because electronic orders can never be delivered

**Correct answer: C.** A transaction has distinct ordering, payment and delivery events.

### Q33. Which request should be treated cautiously?

A) A fictional classroom worksheet with no personal data

B) A saved public product description

C) A printed list of comparison criteria

**D) An unsolicited message asking for a password or one-time code**

**Correct answer: D.** Credential and code requests can be part of a deceptive transaction attempt.

### Q34. Does HTTPS alone prove an unfamiliar shop is trustworthy?

**A) No, seller identity and terms still need review**

B) Yes, all product claims are independently guaranteed

C) Yes, every refund request must automatically succeed

D) No, because websites cannot encrypt connections

**Correct answer: A.** Transport protection is different from seller reliability.

### Q35. Which record can help track an order?

A) Only the mouse's serial number

**B) The relevant order reference and permitted transaction details**

C) Only the monitor's refresh rate

D) Only an unrelated desktop icon

**Correct answer: B.** Order information provides context when checking status or seeking verified support.

### Q36. What is appropriate for a classroom e-commerce demonstration?

**A) A fictional checkout with no real payment or private data**

B) Submitting another person's card details

C) Publishing a real account password

D) Making an unapproved purchase to test a banner

**Correct answer: A.** A model can teach the workflow without exposing data or creating a transaction.

## 7.4 Other Internet Services MCQs

### Q37. Which is an email function?

**A) Sending addressed messages with supported attachments**

B) Only controlling a CPU clock

C) Only turning a pixel on

D) Only formatting an SSD

**Correct answer: A.** Email supports messages between addressed recipients.

### Q38. Does sending an email prove it was read?

A) Yes, every recipient reads immediately

B) Yes, all mail servers require a spoken reply

C) No, because email cannot carry text

**D) No, sending and reading are different events**

**Correct answer: D.** Message status must not be confused with recipient attention.

### Q39. What does Cc normally expose to recipients?

A) Only the sender's processor temperature

B) Only the password hash

**C) The listed copied recipients**

D) Only a printer queue

**Correct answer: C.** Visible recipient fields can reveal addresses.

### Q40. What is an attachment?

A) Only the email application's icon

B) Only the recipient's monitor

C) Only a network cable

**D) A file included with a message**

**Correct answer: D.** Attachments and shared-file links have different delivery and permission behaviour.

### Q41. What does instant messaging support?

A) Only permanent hardware repair

B) Only disk partition formatting

**C) Conversational exchanges through a messaging service**

D) Only offline paper binding

**Correct answer: C.** Messaging services organise exchanges and can support groups and media.

### Q42. What does VoIP carry?

A) Only printed invoices by road

B) Only physical video discs

**C) Voice communication using IP networks**

D) Only computer case screws

**Correct answer: C.** VoIP describes voice communication over IP-based networks.

### Q43. Which item should be reviewed before screen sharing?

**A) The visible window and intended audience**

B) Only the keyboard's purchase date

C) Only the case colour

D) Only a wallpaper's filename

**Correct answer: A.** Screen sharing can expose unrelated or private information.

### Q44. Does traditional FTP itself encrypt credentials and contents?

A) Yes, every FTP session is automatically encrypted

B) Yes, encryption is supplied by the filename

C) No, because FTP cannot transfer files

**D) No, encrypted protection requires an appropriate supported alternative or extension**

**Correct answer: D.** Traditional FTP should not be assumed to provide encrypted protection.

### Q45. What is SFTP?

A) A synonym for every ordinary FTP session

B) Only a screenshot file type

C) Only a social-media button

**D) A distinct SSH-based file-transfer protocol**

**Correct answer: D.** SFTP uses SSH and is not the same protocol as traditional FTP.

### Q46. Does a public download permit modifying the remote server?

A) Yes, any visible file grants administrator access

B) Yes, a download always includes write permission

C) No, because files cannot be downloaded

**D) No, access rights and permitted uses remain separate**

**Correct answer: D.** Reading a public resource does not grant remote write authority.

### Q47. Does deleting one social post guarantee all copies disappear?

A) Yes, every device erases all copies immediately

B) Yes, deletion controls every archive

**C) No, recipients may retain copies or screenshots**

D) No, because posts cannot ever be deleted

**Correct answer: C.** Distribution can create copies beyond the original account's control.

### Q48. Which classroom messaging activity is appropriate?

A) Publishing classmates' private phone numbers

B) Sending unsolicited messages to strangers

**C) A fictional exchange using non-sensitive data**

D) Sharing an account password publicly

**Correct answer: C.** A model can teach communication choices without exposing real people.

## 7.5 Computer Security and Malware MCQs

### Q49. What does confidentiality concern?

**A) Preventing unauthorised disclosure**

B) Only increasing screen brightness

C) Only sorting keyboard keys

D) Only making a file longer

**Correct answer: A.** Confidentiality concerns who can access or learn information.

### Q50. What does integrity concern?

A) Only a fan's speed

B) Only monitor size

C) Only decorative colours

**D) Protection against improper alteration**

**Correct answer: D.** Integrity concerns the correctness and authorised state of information.

### Q51. What does availability concern?

A) Only the number of fonts

**B) Usable access when required under the system's intended conditions**

C) Only a mouse's weight

D) Only a desktop theme

**Correct answer: B.** Availability is a security objective concerning access to systems and data.

### Q52. What is a vulnerability?

A) Every successful backup

B) Every authorised update

C) Only an account's public nickname

**D) A weakness that may be exploited**

**Correct answer: D.** Weaknesses can expose a system to threats.

### Q53. What distinguishes a computer virus in the basic model?

A) It always replaces a monitor physically

B) It is every unsolicited advertisement

**C) It infects suitable host material**

D) It is any slow application

**Correct answer: C.** A virus depends on an infection mechanism involving a host.

### Q54. What can a worm do?

A) Only change the desk position

B) Only print a paper form

C) Only improve every network connection

**D) Propagate between systems without the same host-file infection requirement**

**Correct answer: D.** Worm behaviour includes self-propagation across systems.

### Q55. What describes a Trojan?

A) Every encrypted backup

**B) Malicious behaviour concealed behind a useful or legitimate appearance**

C) Every approved printer driver

D) Only a hardware cable fault

**Correct answer: B.** Deceptive presentation can induce a user to run malicious code.

### Q56. Must phishing install malware to cause harm?

A) Yes, stolen passwords require a virus file

B) Yes, every false website is harmless without installation

C) No, because messages cannot deceive people

**D) No, it can deceive a user into giving information**

**Correct answer: D.** Credential theft can occur through a deceptive request or page.

### Q57. Which is a layered safeguard?

A) Disabling every update permanently

B) Using one password for all accounts

**C) Updates, access controls, MFA and checked backups together**

D) Running unknown files to see their effect

**Correct answer: C.** Multiple safeguards address different failure paths.

### Q58. Does MFA remove every need to review sign-in requests?

A) Yes, every approval request is safe

**B) No, deceptive prompts and other threats still matter**

C) Yes, passwords can then be published

D) No, because MFA cannot add protection

**Correct answer: B.** MFA is an additional layer, not universal immunity.

### Q59. What makes a backup operationally useful?

A) Only its filename includes backup

B) Only its icon is green

C) Only it is stored beside the original

**D) Required data can be restored from it**

**Correct answer: D.** Recoverability needs checking rather than assuming a copy is sufficient.

### Q60. What is a suitable response to a suspicious attachment at school?

A) Execute it on every classroom computer

B) Forward it to all friends

**C) Stop interacting and report through authorised support**

D) Publish staff passwords to ask for help

**Correct answer: C.** Follow incident procedures without spreading the suspected threat.

## 7.6 Information Privacy MCQs

### Q61. What is a central information-privacy question?

**A) How personal information is collected, used and shared**

B) Only how bright the display is

C) Only which processor brand is installed

D) Only how fast a fan rotates

**Correct answer: A.** Privacy addresses appropriate handling of information relating to people.

### Q62. Are security and privacy identical?

**A) No, secure storage alone does not justify every collection or use**

B) Yes, every encrypted database is automatically appropriate

C) Yes, privacy only means antivirus installation

D) No, because privacy never concerns information

**Correct answer: A.** Security safeguards and appropriate personal-data use are related but distinct.

### Q63. What is data minimisation?

A) Collecting all available personal details by default

**B) Limiting data to what is appropriate for a stated purpose**

C) Publishing every account field

D) Keeping unnecessary copies indefinitely

**Correct answer: B.** Collecting fewer unnecessary details reduces avoidable exposure.

### Q64. Which dataset suits a public classroom demonstration?

**A) Fictional records with only needed fields**

B) Real students' identity numbers

C) Unredacted family contact lists

D) A private staff payroll

**Correct answer: A.** Fictional minimal data can teach the task without disclosing real records.

### Q65. What should be checked before sharing a document link?

A) Only the document icon

**B) Audience and view or edit permissions**

C) Only the browser's theme

D) Only the monitor size

**Correct answer: B.** Link access can extend beyond the intended audience if roles are wrong.

### Q66. Can comments in a document disclose information?

A) No, only the first visible heading can disclose data

B) No, comments are always automatically public-safe

**C) Yes, review comments and other included material**

D) Yes, but only when printed in red

**Correct answer: C.** Content outside the main body can still contain private details.

### Q67. Does removing a name always make a record unidentifiable?

A) Yes, every remaining field is automatically anonymous

B) Yes, photographs cannot identify anyone

**C) No, other details may reveal the person**

D) No, because names can never be removed

**Correct answer: C.** Identification can arise from combinations of remaining information.

### Q68. Are all cookies malware?

A) Yes, every cookie is an executable virus

B) Yes, a website cannot use cookies for sessions

C) No, because browsers cannot store data

**D) No, cookies have different uses and properties**

**Correct answer: D.** Cookies should be assessed by their actual purpose and handling.

### Q69. Does private browsing provide universal anonymity?

A) Yes, websites cannot receive any requests

**B) No, it does not hide activity from every external party**

C) Yes, network operators cannot observe any activity

D) No, because it permanently publishes all history

**Correct answer: B.** Private mode has a limited browser-session scope.

### Q70. What should a privacy setting be understood through?

A) Only its colour

B) Only the length of its label

**C) Its supported scope and limitations**

D) A guarantee that all tracking everywhere stops

**Correct answer: C.** Settings cannot be assumed to control every service or observer.

### Q71. Does permission for one use automatically permit every future use?

**A) No, review the proposed purpose and permission**

B) Yes, permission is unlimited forever

C) Yes, a photograph has no audience restrictions

D) No, because permission can never be given

**Correct answer: A.** Permission should match the intended use and relevant requirements.

### Q72. What should follow an accidental private-data disclosure?

A) Copy it into more public groups

B) Ignore every institutional procedure

C) Ask classmates to repost it

**D) Report it through the approved responsible channel**

**Correct answer: D.** Timely authorised handling can limit further exposure.

**B) Responsible decisions and effects of computing**

**Correct answer: B.** Ethics considers responsibilities and effects on people.

### Q74. Does technical possibility alone justify an action?

### Q75. Which is honest academic conduct?

### Q78. What should a student do after finding an exposed private folder?

### Q79. Which design improves an error message's accessibility?

### Q80. Does automation remove responsibility for unfair outcomes?

**A) No, data and design still need review**

### Q81. Which test record is ethical?

A) A fabricated success screenshot

### Q82. What should follow discovery of an error in a published result?

A) Keep the false claim to protect appearances

B) Blame an unrelated user without evidence

C) Invent supporting measurements

**D) Correct the record and explain the relevant limitation**

**Correct answer: D.** Accountability includes correcting known errors.

### Q83. Which communication respects others?

A) Publishing threats to win an argument

**B) A clear disagreement without harassment or impersonation**

C) Pretending to be another student

D) Exposing private details as a joke

**Correct answer: B.** Respectful participation avoids misleading and harmful conduct.

### Q84. What should a project record include?

A) Only promotional claims

B) Only the developer's favourite colour

**C) Permitted sources, real test outcomes and limitations**

D) Only invented user feedback

**Correct answer: C.** A useful record allows others to assess both work and constraints.

## Easy topic-wise notes

## 7.1 Networks, Internet Access and Addresses

A computer network connects devices so they can exchange data and use permitted resources. A classroom local network can connect computers with a printer or file service. The Internet is a global interconnection of networks using shared communication protocols. A local Wi-Fi connection and a working Internet connection are different things: a device can be connected to a router while the external service is unavailable.

An Internet service provider, or ISP, supplies an access service. Connection methods can include fibre, cable, DSL, mobile networks or satellite. Required equipment and practical performance depend on the service and installation. A router forwards traffic between networks; a wireless access point supplies a supported wireless connection. One product can combine functions, but router, access point and modem do not mean the same function in every installation.

Data is carried in organised units such as packets. Different links and routers can participate in delivery. Packets need not all follow an identical path or arrive at exactly the same time. Reliability, ordering and recovery depend on the protocols and application. TCP can provide an ordered reliable byte stream, while other Internet traffic can use different transport designs. Do not describe every Internet service as having one universal delivery behaviour.

An IP address identifies an interface for Internet Protocol communication within its applicable scope. IPv4 and IPv6 use different address formats and sizes. A domain name provides a human-readable name, and DNS resolves relevant names to records, which can include IP addresses. A name is not necessarily permanently tied to one server or address. An entire web address can also contain a scheme, path and other components beyond the host name.

Upload sends data from the user's side toward a remote service; download receives it. Bandwidth or advertised link rate is different from the actual speed of one transfer, and latency describes delay rather than capacity. Bits and bytes also differ: eight bits make one byte. A nominal 100 megabits per second corresponds arithmetically to 12.5 megabytes per second before overhead and other limitations. This is a unit-conversion example, not a guaranteed service speed.

For a connection problem, first distinguish device-to-network access, external connectivity, name resolution and the particular service being requested. A website being unavailable does not prove the whole Internet is down. Use permitted observations and support procedures rather than changing unrelated settings or attempting access to other users' systems.

### Practical examples

- A laptop reaches a local printer while an ISP outage prevents external browsing.
- A familiar domain name can resolve to different supported addresses as a service changes its infrastructure.
- A 100 Mb/s label uses bits; 12.5 MB/s is only its simple theoretical byte-rate equivalent before overhead.

### Common mistakes

- Connected to Wi-Fi does not automatically mean connected to the Internet.
- DNS resolves names and records, not every full URL as one indivisible address.
- Advertised rate, actual throughput and latency are different properties.

### Quick revision

- Networks connect devices; the Internet connects networks.
- ISPs provide access through different service methods.
- Routers forward network traffic.
- Packets and transport protocols support data delivery.
- Domain names, DNS and IP addresses have distinct roles.
- Distinguish bits, bytes, throughput and delay.

## 7.2 The World Wide Web and Web Publishing

The World Wide Web is a system of linked resources commonly accessed using web technologies over the Internet. The Internet supplies network connectivity; the Web is one major use of it. Email, file transfer and other services show why the two terms are not interchangeable. A browser retrieves and presents web resources. A search engine helps locate indexed material and is a service reached through a browser or other interface.

A URL identifies a resource using a structured address. In a simplified HTTPS example, the scheme names the access method, the host identifies the service name, and a path identifies a resource within it. Query parameters can supply additional request information and a fragment can identify a position or target within a document. A domain name is only one part of many URLs. Similar-looking names can belong to different services, so inspect the actual host rather than trusting a familiar word anywhere in the address.

Navigation can use links, menus, back/forward controls, bookmarks and direct address entry. A link's visible text is not proof of its destination. Web pages can change, redirect or become unavailable. Refresh requests an updated representation according to browser, server and caching behaviour; it does not guarantee that every upstream data source has already updated.

Search queries can combine specific terms, names and context. The first result is not automatically the most authoritative source, and a snippet can be incomplete or old. Distinguish advertisements from other results where labelled, open the relevant page and compare its author, date, evidence and purpose. Official notices are preferable for official deadlines; a discussion post may describe an experience without establishing a general rule.

Websites can serve educational, commercial, government, news, entertainment, reference or community purposes. A single site can combine several functions. A domain suffix alone does not prove that every page is correct or current. HTTPS supports transport protection to the named service; it does not certify every statement made on the site. Browser security indicators and source evaluation answer different questions.

Web publishing makes prepared content available to its intended audience through a web service. A workflow includes planning, creating content, checking accessibility and links, placing files or records on the supported hosting system, and verifying the published result. A local preview is not automatically a public publication. Updating a page also requires checking the delivered version, source attribution, permissions for reused material and any private information that should not be exposed.

### Practical examples

- A browser opens a board notice; a search engine result helps locate it but is not itself the board notice.
- A student checks the host and destination before following an unfamiliar login link.
- A publisher verifies the public page after upload rather than treating a local preview as publication.

### Common mistakes

- The Web is not the entire Internet.
- A browser and a search engine have different roles.
- HTTPS and a familiar-looking domain suffix do not verify every page statement.

### Quick revision

- The Web provides linked resources.
- Browsers present resources; search services help find them.
- URLs have meaningful components.
- Link text and destination can differ.
- Evaluate source, context and date.
- Publishing requires checking the delivered page.

## 7.3 E-Commerce

Electronic commerce uses electronic systems to support the buying and selling of goods or services and related transactions. A website or app can display a catalogue, accept an order, arrange payment and provide fulfilment information. Browsing a product page, placing an order, paying and receiving the item are different stages. A confirmation message may identify a stage without proving every later obligation has been completed.

Business-to-consumer, or B2C, describes a business selling to an individual consumer. Business-to-business, or B2B, concerns transactions between businesses. Consumer-to-consumer, or C2C, can describe individual sellers and buyers using a marketplace. A platform's role must be checked: it may operate a marketplace rather than manufacture or personally fulfil every listed product. Names and logos alone do not establish the identity or reliability of a particular seller.

Compare the complete transaction rather than one headline price. Quantity, delivery charge, taxes or other applicable charges, discounts and conditions can affect the final amount. In a fictional exercise, an item amount of 1,000 plus delivery of 150 minus a valid discount of 100 gives 1,050. The example assumes no other charges. Real terms require current verification rather than a universal formula for every checkout.

Payment can use supported methods such as an approved card service, transfer or cash-on-delivery arrangement, depending on the seller and service. A payment method does not itself guarantee product quality or the outcome of a dispute. Verify the intended payment destination through a trusted path and do not disclose passwords, card secrets or one-time codes in response to unsolicited messages. HTTPS alone is not proof that an unfamiliar shop is trustworthy.

Before a purchase, inspect the seller, product description, total amount, delivery terms and return/refund conditions. A review can be useful evidence but may be incomplete, biased or fabricated. Retain the relevant order reference and permitted transaction records. Handle addresses and other personal information carefully. A classroom exercise should use fictional data and a paper checkout rather than submitting a real payment or opening an unneeded account.

E-commerce can support access and convenience, but it also depends on connectivity, inventory, fulfilment and support. An order status such as placed, paid, shipped or delivered describes different events. Read the service's definitions and seek help through its verified support route when needed. This lesson explains transaction concepts and checking habits rather than promising that any platform, payment method or offer is risk-free.

### Practical examples

- A retailer sells a notebook to a student through an online catalogue: a B2C example.
- A fictional checkout totals 1,000 plus 150 delivery minus a valid 100 discount, giving 1,050 before any other stated charge.
- A buyer checks the seller and order terms rather than relying only on an attractive discount banner.

### Common mistakes

- A product listing, a paid order and delivered goods are different states.
- A marketplace is not necessarily the manufacturer or fulfiller of every listing.
- A secure connection is not a guarantee about the seller or product.

### Quick revision

- E-commerce supports electronic transactions.
- B2C, B2B and C2C describe participant relationships.
- Check the complete payable amount.
- Verify the intended payment destination.
- Retain relevant order records.
- Use fictional data for classroom checkout exercises.

## 7.4 Other Internet Services

The web is one Internet-based service family. Email, messaging, voice calls and file transfer use Internet connectivity for different purposes. A browser can provide an interface to several of them, but the interface does not make all their underlying functions identical. Select a service by the communication need, supported features, recipients and data sensitivity.

Email supports addressed messages and attachments. To, Cc and Bcc have different recipient-display roles. Review recipients before sending, and do not assume that Bcc prevents someone from forwarding the contents. An attachment is a file included with a message; a shared-file link points to material managed elsewhere and may require permission. Sending a message does not prove it has been read or that a requested action is complete.

Instant messaging supports conversational exchanges, sometimes with groups and media. Presence indicators and read receipts depend on the service and settings; they are not universal guarantees about a person's attention. Voice over Internet Protocol, or VoIP, carries voice communications using IP networks. Video conferencing adds visual participation and can include screen sharing. Audio, video and screen content can disclose different information, so check the active source and audience before sharing.

FTP is a file-transfer protocol. Traditional FTP does not itself protect credentials and contents with encryption. SFTP is a distinct SSH-based transfer protocol; it is not simply another spelling of FTP. Secure transfer choices depend on the supported service and policy. A public download being accessible does not grant permission to upload, modify or redistribute its contents.

Social media supports publication and interaction through accounts, feeds, groups or communities. A post's visible audience, redistribution and persistence deserve review. Deletion from one account does not guarantee removal of copies or screenshots. For a class activity, use fictional messages or an already approved account, and record the service choice without contacting strangers or sharing personal information.

### Practical examples

- An email attachment travels with a message; a restricted drive link may still deny the recipient access.
- A class presenter shares one intended window after checking that private tabs are hidden.
- A service administrator chooses an approved encrypted file-transfer method rather than assuming every FTP connection is encrypted.

### Common mistakes

- Email delivery and reading are different events.
- SFTP and FTP are different protocols.
- A private-looking social post can still be copied by a recipient.

### Quick revision

- Email supports addressed messages.
- Messaging supports conversations.
- VoIP carries voice over IP networks.
- Conferencing can expose camera, microphone and shared-screen content.
- Traditional FTP lacks built-in encrypted protection.
- Check audience, permissions and permitted reuse.

## 7.5 Computer Security and Malware

Computer security protects systems and information against threats affecting confidentiality, integrity and availability. A threat is a potential cause of harm; a vulnerability is a weakness that can be exploited. An attack is an attempt to cause an unauthorised outcome. A fault or outage should be investigated rather than automatically labelled a deliberate attack.

Malware is malicious software or code. A virus spreads by infecting a host file or other suitable host material. A worm can propagate between systems without needing that same host-file mechanism. A Trojan presents itself as useful or legitimate to induce execution while concealing malicious behaviour. These descriptions concern behaviour; modern incidents can combine several techniques. A suspicious filename alone is not a reliable diagnosis.

Ransomware can deny access or be combined with theft and extortion. Phishing uses deceptive communications to obtain information or induce unsafe actions. A phishing message does not have to contain malware: a false sign-in page can steal credentials. Recognisable branding, urgent wording and a familiar sender display name do not independently prove authenticity. Check requests through a known, independently obtained channel.

Use layered safeguards: supported updates, trustworthy sources, access control, strong unique passwords, supported multi-factor authentication, protective tools and checked backups. MFA adds a factor beyond a password, but users must still review prompts and resist deceptive requests. A backup is useful only when the required information can actually be recovered. A continuously connected writable copy can be affected by the same incident.

If a suspected incident occurs, follow the institution's reporting procedure, stop the risky interaction and seek authorised support. Preserve relevant observations without forwarding malicious files to classmates. Do not experiment by executing a suspicious attachment or attacking an external system. Recovery can require credential changes, isolation, investigation and restoration under authorised guidance. No single product or habit makes a computer immune to all threats.

### Practical examples

- A false email asks a student to sign in at an unrelated address; the student checks the request through the known school contact.
- A Trojan-labelled example describes deceptive installation, not a laboratory instruction to run unknown software.
- An administrator tests restoring a permitted sample from a retained backup.

### Common mistakes

- Phishing can steal information without installing malware.
- A Trojan and a virus describe different behaviours.
- Antivirus software and backups are useful layers, not absolute guarantees.

### Quick revision

- Confidentiality limits disclosure.
- Integrity protects against improper changes.
- Availability concerns usable access.
- Distinguish threats, weaknesses and attacks.
- Use layered safeguards and verified recovery.
- Report suspected incidents through authorised channels.

## 7.6 Information Privacy

Information privacy concerns appropriate collection, use, access, sharing and retention of information relating to people. Security and privacy overlap but are not interchangeable. A service might securely store a large amount of unnecessary personal data; protection against intrusion does not by itself establish that the collection and use are appropriate.

Start with purpose. Identify what information is needed for a particular task, who needs it and how long it should be retained. Data minimisation means limiting collection and processing to what is appropriate for that purpose. A classroom marks exercise can usually use fictional names or identifiers rather than real addresses, identity numbers or family details. Avoid copying private data into public demonstration files.

Review permissions before sharing. View, comment and edit roles may grant different powers, and an unrestricted link can reach people beyond the intended recipients. Check document contents as well as the sharing setting: names in comments, tracked changes, images or metadata may disclose information. Removing a person's name does not always prevent identification when other details remain sufficiently revealing.

Browsers and online services can store cookies, local data and account history for different functions. Cookies are not all the same, and not every cookie is malware. A privacy setting changes supported behaviour within its stated scope; it is not a promise that no party can observe activity. Private browsing mainly limits certain records retained in that browser session and does not make a user anonymous to every website, employer or network operator.

Before publishing another person's photograph or details, check the permission, purpose and applicable institutional requirements. Consent should be meaningful and relevant to the proposed use; one permission does not automatically authorise every later use. If accidental disclosure occurs, notify the responsible person through the approved procedure. Privacy protection is a continuing practice across collection, use, sharing and deletion, not one checkbox at account creation.

### Practical examples

- A practice registration form uses fictional learners and collects only fields necessary for the exercise.
- A teacher checks that a class document link is limited to the intended group.
- A screenshot is reviewed for names and account details before inclusion in a public lesson.

### Common mistakes

- Private browsing is not universal anonymity.
- Removing names alone may leave identifying combinations of details.
- A secure database can still contain data collected for an inappropriate purpose.

### Quick revision

- Identify the purpose before collecting data.
- Minimise unnecessary personal details.
- Review roles, content and recipients.
- Check retention and deletion requirements.
- Privacy settings have defined limits.
- Use fictional data for public classroom examples.

## 7.7 Computer Ethics

Computer ethics concerns responsible choices in designing, using and managing computing systems. A technically possible action is not automatically appropriate. Consider affected people, foreseeable harm, honesty, fairness, privacy and professional responsibility. Legal requirements and institutional rules matter, while ethical judgement can also require care where a rule does not describe every detail.

Honesty includes representing work and evidence accurately. Do not claim that a copied solution is your original work, invent a research result or alter a screenshot to imply a test succeeded. When using another person's text, images, code or data, check the permission or licence and provide the required attribution. Giving credit alone does not automatically supply permission for every use. Openly available material is not necessarily free of copyright or other restrictions.

Respect authorised access. Being able to guess a password or reach an exposed folder does not mean permission has been granted. Use only the systems, accounts and data within the agreed task. Report an apparent weakness through the responsible channel rather than exploring other people's files. Curiosity should be expressed through approved exercises and deliberately prepared training environments.

Fairness and accessibility matter in ordinary classroom software too. A colour-only warning can be difficult for some users to interpret; meaningful labels and sufficient contrast can help. Evaluate systems using relevant evidence rather than assumptions about users. A decision aid may reproduce problems in its data or design, so human responsibility is not removed by calling the output automated.

In a class project, document the source of assets, actual test results, permitted data and limitations. If an error is found, acknowledge it and correct the record. Respectful online communication avoids harassment, impersonation and misleading presentation. Good computing practice combines useful results with care for the people who create, use or are affected by those results.

### Practical examples

- A student cites a permitted image and follows its licence conditions.
- A developer records that one browser test failed instead of hiding the result.
- A form displays a text explanation beside an error colour so more users can understand it.

### Common mistakes

- Publicly accessible does not mean unrestricted reuse.
- Attribution alone does not always provide permission.
- Technical ability is different from authorised access.

### Quick revision

- Consider harm and affected people.
- Represent work and test evidence honestly.
- Respect access boundaries and licences.
- Design for fair and accessible use.
- Document limitations and correct errors.
- Communicate respectfully.

## 7.8 Cybercrimes and Responsible Reporting

Cybercrime broadly concerns unlawful acts involving computers, networks or digital information. Examples studied in introductory computing include unauthorised access, digital fraud, identity misuse and unlawful interference with data or services. Whether a specific incident satisfies a legal offence depends on the applicable law and facts. A class note is not a legal determination about a particular person.

Pakistan has electronic-crime legislation and official investigation and reporting arrangements. Requirements and institutions can change, so consult current official Pakistani sources for an actual complaint. Do not rely on an old social-media screenshot for legal provisions, penalties or complaint contacts. This chapter teaches recognition and responsible handling rather than memorising potentially outdated punishment amounts.

Authorisation has scope. Permission to read a sample folder does not necessarily allow deletion, publication or access to another account. A classroom security exercise should define the systems, actions and time allowed. Activities outside that scope require proper authorisation. Do not test guessed passwords or exploit a public website as a practice task.

Digital fraud can involve impersonation, false payment requests or fabricated offers. Verify unexpected requests using contact details obtained independently from a known source. Do not send money, credentials or one-time codes merely because a message creates urgency. Preserve relevant message text, dates, account identifiers and transaction references when appropriate, without editing the original evidence or redistributing private material publicly.

For an incident in an institution, notify the responsible authorised contact and follow its process. For an actual suspected offence, use the current official reporting route and suitable professional advice where needed. Keep allegations factual: record what was observed, what remains uncertain and what has already been done. Publicly accusing an identified person based only on a rumour can cause further harm. Training should use fictional scenarios and approved environments, with no malicious files or real victims.

### Practical examples

- A lab permission allows reading one sample dataset, not deleting other folders.
- A fictional payment request is checked through the organisation’s independently known contact.
- A student records the time and relevant message reference, then follows the institution’s reporting procedure.

### Common mistakes

- Knowing a password does not automatically establish permission to use the account.
- An old penalty chart may not describe current law.
- A classroom suspicion is not a legal finding of guilt.

### Quick revision

- Cybercrime examples concern unlawful digital acts.
- Legal conclusions depend on law and facts.
- Authorisation has a defined scope.
- Verify requests independently.
- Preserve relevant evidence responsibly.
- Use current official reporting information.

## 7.9 Health Concerns and Comfortable Computer Use

Computer use involves the person, workstation, task and work routine. Poorly arranged equipment or long periods in an uncomfortable position can contribute to discomfort, fatigue and eye strain. A useful classroom review considers the whole setup rather than claiming that one accessory prevents every problem.

Arrange the screen so the task can be read comfortably without prolonged awkward neck positioning. Adjust text size, viewing arrangement and lighting to reduce unnecessary leaning and glare. Position the keyboard and pointing device so they can be used without sustained reaching or an awkward wrist position. A suitable chair and supported working position should fit the user and task; people and equipment differ, so one fixed measurement is not a universal solution.

Vary tasks and include suitable breaks or changes of activity rather than maintaining one static position for a long period. A break from keyboard work is less useful if it simply repeats the same uncomfortable posture and intense near-screen activity on another device. Local school or workplace arrangements should support an appropriate routine. The cited UK guidance supplies practical workstation principles; its legal provisions are not presented as Pakistani legal entitlements.

Laptops combine the screen and keyboard, which can make extended comfortable positioning harder. Where available and appropriate, a separate keyboard, pointing device or supported display arrangement can help adapt the workstation. Avoid balancing equipment in an unstable position or blocking its ventilation. Keep walkways clear of cables and follow authorised electrical-safety and maintenance arrangements; students should not open powered equipment to solve a comfort issue.

Report persistent pain, visual problems or other concerning symptoms to an appropriate responsible person and seek qualified health advice when needed. Do not diagnose a condition from a class exercise or promise that a particular posture will cure it. The learning goal is to identify avoidable strain, improve the working arrangement and ask for suitable support, while treating individual needs respectfully.

### Practical examples

- A learner increases text size rather than leaning forward to read small letters.
- A classroom review identifies screen glare, a distant mouse and a cable across a walkway.
- A laptop user plans an appropriate supported setup for longer tasks using available approved equipment.

### Common mistakes

- One rigid posture is not a universal cure.
- A move to another screen may repeat the same strain.
- A classroom checklist cannot diagnose persistent symptoms.

### Quick revision

- Review person, workstation and task together.
- Improve readable text, lighting and equipment position.
- Avoid prolonged awkward reaching and static positions.
- Vary activities and use suitable breaks.
- Keep equipment stable and walkways clear.
- Seek qualified advice for persistent problems.

## Solved short questions

### 1. Distinguish the Internet and the World Wide Web.

The Internet is an interconnection of networks. The web is a system of linked resources accessed using web technologies over that infrastructure. Email and other services can also use the Internet.

### 2. Distinguish an ISP, router and access point.

An ISP provides an access service. A router forwards traffic between networks, while an access point provides a supported wireless connection. One device can combine roles without making their functions identical.

### 3. How do an IP address, domain name and URL differ?

An IP address supports network addressing. A domain name is a human-readable name resolved through DNS records. A URL identifies a resource using components such as scheme, host and path; it is more than just a domain name.

### 4. Distinguish a browser and a search engine.

A browser retrieves and presents web resources. A search engine indexes resources and answers queries through a service often opened in a browser. A result snippet is not a substitute for checking the source page.

### 5. What does web publishing involve?

Prepare permitted material, organise resources, test links and accessibility, then place the checked resources in the intended public hosting environment. Verify the public result. A local preview is not proof of a successful publication.

### 6. Compare B2C, B2B and C2C transactions.

B2C connects a business seller with an individual consumer. B2B describes transactions between businesses. C2C concerns individuals trading with other individuals, often through a marketplace. A platform and its listed seller may have different roles.

### 7. Compare email, messaging and VoIP.

Email supports addressed messages and attachments. Messaging supports conversational exchanges. VoIP carries voice over IP networks; conferencing can add video and screen sharing. Choose by the task and review audience and privacy.

### 8. Distinguish a virus, worm and Trojan.

A virus infects host material. A worm can propagate between systems without the same host-file requirement. A Trojan conceals malicious behaviour behind a useful or legitimate appearance. An incident can combine behaviours.

### 9. How do security and information privacy differ?

Security safeguards confidentiality, integrity and availability. Privacy also asks whether personal information is appropriately collected, used, shared and retained. Secure storage alone does not justify collecting unnecessary information.

### 10. Give two computing-ethics responsibilities.

Represent sources and test results honestly, and respect the scope of authorised access. Also review licences and required credits, protect personal data and consider accessibility and foreseeable harm.

### 11. How should a suspected digital offence be documented?

Record relevant observed facts, times and references without altering original evidence or spreading private material. Separate uncertainty from conclusions, follow institutional procedures and consult current official reporting information for an actual complaint.

### 12. What can improve comfortable computer use?

Review readable display position, lighting, keyboard and pointing-device reach, supported seating and task variation. Keep equipment stable and cables out of walkways. Persistent symptoms require appropriate reporting and qualified advice rather than a classroom diagnosis.

## Solved long questions

### 1. Explain how a learner reaches a web resource through an Internet connection.

**Access.** A device connects through a permitted local link and access service. A router forwards traffic between networks; a wireless connection to the router alone does not prove external connectivity. The ISP supplies the relevant external access service.

**Addressing.** A URL supplies the resource address, including a scheme, host and possible path. DNS resolves relevant names to records such as addresses. Names and network addresses have different roles and may change independently.

**Communication.** Requests and responses travel through links and routers in packets. Protocols determine delivery behaviour; not every service has identical reliability or timing. Throughput, latency and advertised capacity measure different properties.

**Review.** The browser presents the response. Check the actual domain, source and context; successful loading and HTTPS do not independently establish that claims are true. Diagnose local access, external connectivity and service failure separately.

### 2. Describe a responsible search and web-publication workflow.

**Find and assess.** Use focused terms and inspect the actual source, date and supporting context. Compare relevant reliable sources rather than treating a popular result as proven. A browser is the client; the search engine is a separate service.

**Prepare.** Write accurate original material and obtain permission for reused assets. Organise headings and navigation, use meaningful links and provide useful text alternatives where appropriate. Avoid publishing private classroom records.

**Test and publish.** Check local content, links and the intended reading experience. Use the authorised hosting process, then open the public address. A working local preview does not prove that all resources reached the server.

**Maintain.** Verify that the public material and links work, correct known errors and update relevant information. Keep a suitable source copy. Publishing and reviewing are continuing responsibilities rather than a one-time upload.

### 3. Explain e-commerce and suitable checks for an online transaction.

**Relationships.** B2C describes business-to-consumer sales, B2B business transactions and C2C individual-to-individual trading. A marketplace can connect independent sellers and buyers; identify which party supplies the goods and handles the relevant obligation.

**Workflow.** A typical model includes selection, checkout, payment, fulfilment and support. These are different events: paid does not necessarily mean delivered. Record the relevant order reference and check actual status rather than relying on a decorative confirmation.

**Cost and conditions.** Compare the complete payable amount, delivery, valid discounts and applicable conditions. In the fictional example, 1,000 plus 150 delivery minus a 100 discount equals 1,050 before any other stated charge.

**Safety.** Review the seller and request independently. HTTPS protects the connection but does not guarantee a shop is trustworthy. Do not disclose passwords or one-time codes in response to an unsolicited request. Classroom demonstrations should use fictional payments and data.

### 4. Compare Internet communication and file-transfer services.

**Messages.** Email supports addressed messages and attachments; recipient fields and sharing links need review. Instant messaging supports conversational exchanges, sometimes with groups. A delivery or presence indicator is not universal proof that a person read or understood the content.

**Real-time communication.** VoIP carries voice using IP networks. Video conferencing can add camera and screen sharing. Check the intended microphone, camera, window and audience; close or hide unrelated private content before sharing.

**Files.** FTP transfers files but traditional FTP does not itself encrypt credentials and contents. SFTP is a distinct SSH-based protocol. Use the transfer method approved and supported for the data and destination; public read access does not grant write authority.

**Publication.** Social media supports posts and interactions with differing audiences. Review privacy and reuse before posting. Removing the original does not guarantee erasing recipients’ copies. Select the service by purpose, permissions and supported features.

### 5. Describe layered security, privacy and responsible incident handling.

**Threats.** Malware includes behaviours such as host infection, self-propagation and deceptive installation. Phishing may steal credentials without installing software. An outage alone is not proof of a deliberate attack; observations require investigation.

**Safeguards.** Use supported updates, trustworthy sources, limited access, unique passwords, supported MFA and checked recoverable backups. No one layer guarantees immunity. Review unexpected requests through independently known channels and do not run unknown files as experiments.

**Privacy and ethics.** Collect appropriate minimal data, review audiences and retention, and use fictional records for public demonstrations. Respect licences, honest reporting and authorised scope. Secure storage does not independently justify an unnecessary collection or disclosure.

**Response.** Stop risky interaction and follow authorised support procedures. Preserve relevant facts without alteration or public redistribution. Legal conclusions depend on applicable law and facts; use current official Pakistani information for actual reporting rather than an old social-media penalty chart.

### 6. Plan a responsible and comfortable classroom computing session.

**Prepare.** Choose a permitted service and use fictional or authorised information. Define access scope and expected output. Check source permissions and the intended audience before collecting or publishing anything.

**Arrange.** Review screen readability and glare, input-device reach, seating, equipment stability and clear walkways. Adapt available equipment to the person and task rather than imposing one rigid arrangement on everyone. Do not open powered equipment.

**Work.** Vary tasks and use appropriate breaks or changes of activity. Check recipients and screen-sharing content. Record actual test results and any limitations honestly, and correct known errors instead of fabricating success.

**Review and seek support.** Save the required output, confirm sharing permissions and retain useful source work. Report security concerns through the authorised route. Persistent pain or visual problems need appropriate qualified advice; a classroom checklist does not diagnose or guarantee a cure.

## Practical activities and viva preparation

### Map a permitted connection

Draw a classroom device, local access link, router, ISP and a public web service. Label the URL, DNS and IP roles. Explain how local Wi-Fi can remain connected during an external-service outage. Do not change network settings.

**Expected result:** A labelled conceptual diagram distinguishing local access, Internet infrastructure and web resources.

### Assess and plan a web page

Use two public permitted sources for a non-sensitive topic. Record their authorship, dates and evidence; plan a page with headings, descriptive links and a permitted image credit. If no publishing environment is authorised, keep the work as a local or paper plan.

**Expected result:** A source assessment and publishing checklist with local testing and public verification as separate stages.

### Model a purchase and service choice

On paper, classify fictional B2C, B2B and C2C examples. Calculate a 1,000 item plus 150 delivery minus a valid 100 discount. Choose email, messaging, VoIP or a file-transfer service for three stated classroom tasks and justify each.

**Expected result:** A total of 1,050 under the stated assumptions, correct transaction roles and reasoned service choices.

### Review a fictional suspicious request

Use a teacher-written fictional payment or sign-in request with no active malicious links. List warning signs, an independently known verification route, relevant evidence and the authorised reporting contact. Do not send messages, pay money or execute files.

**Expected result:** A response plan separating observation from allegation and respecting privacy and access scope.

### Audit privacy and workstation comfort

Inspect a fictional shared-document scenario and an available workstation. Identify unnecessary personal fields, wrong sharing roles, readability, glare, reaching, stability and cable issues. Suggest permitted adjustments and task variation; do not diagnose anyone or open equipment.

**Expected result:** A practical checklist covering appropriate data use, intended audience, comfortable work and escalation of persistent concerns.

How can workstation arrangement and task variation help? Check the topic notes and solved answers for explanations.
